## 2. Decisions

- Several small, swappable models instead of one big model; heavy work on Kaggle (2x Tesla T4) because Joshua's own machine is not a GPU box.
- Defect detector: YOLO26s fine-tuned on RDD2022 (classes 0 longitudinal_crack, 1 transverse_crack, 2 alligator_crack, 3 pothole).
  RF-DETR-S was prepared as a challenger (notebook 02) but never run.
- Road filter: SegFormer-B0 (Cityscapes) so detections off the road are dropped.
- Tracking: BoT-SORT + a custom track-merge pass (merge fragments/duplicates, class vote, min frames, min confidence) = "report once".
- Masks/area: SAM 2 on each defect's best frame.
- Vehicles (bonus): a COCO YOLO26 scene detector with the same tracker.
- Permission given by Joshua: download what we need and upload what we need. Videos stay private.

### Day 3 - Fri 16/10 (new asks: markings / signs / lights + stable, past-only decisions)
Asks (Joshua): detect road markings, road signs/boards and traffic lights and flag them when damaged/faded/broken; make every
decision stable like a left-only attention window - no flicker (a defect seen in frame 1 and gone in frame 2, speed 40 -> 0 ->
40): previous results must weigh into the current ones, no look-ahead.

Built (code v3, `roadscan-code_v3.zip`, 23 unit tests pass):

| Module | What it does |
|---|---|
| `temporal.py` | EMA, causal trimmed mean, rate limiter, `SpeedFilter`, `DwellState` (hysteresis + dwell), `DecayedVotes`, `TrackScore`/`TrackMemory`, `TemporalPrior` (previous confirmed tracks feed back into the next detection step: confidence blend + class vote inside the crack group) |
| `furniture.py` | Mapillary-Vistas Mask2Former (swin-large) every 4 frames -> lane markings, crosswalks, signs, lights, poles; condition cues: paint contrast + segmenter confidence vs a causal running reference (markings/crosswalks), pole/face lean + weak CLIP (signs), HSV lamp state voted over time (lights); outputs `road_furniture.csv/json`, `marking_visibility.csv`, new defect classes 6-9 |
| `odometry.py` | speed is now causal (trimmed mean -> EMA -> accel 3.5 / decel 6 m/s^2 limiter); distance integrates the filtered speed |
| `surface.py` | trailing (past-only) smoothing + hysteresis + 1.5 s dwell for paved/unpaved/sidewalk |
| `pipeline.py` | wiring: prior feedback, confirmed-only drawing with 3-frame coast, marking paint overlay (green ok / red worn), inventory boxes, HUD line |

Findings while testing:
- clipB has duplicated frames: per-frame speed alternates 4.8 / 9.6 km/h. The old centred *median* gave 5.9 km/h vs the true mean
  7.4 km/h (-20 %). Fixed by using a trimmed mean (keeps the average, still rejects 3-frame dropouts).
- Mapillary Mask2Former works well on real frames: continuous lane lines, signs with poles, traffic lights; nothing falsely found on
  the rural clipB. It draws dashed lines as continuous strokes, so paint contrast is measured on the brightest quarter of the mask.
- CLIP zero-shot on tiny sign crops (10x24 px) is noise (always "hidden behind vegetation"); it only runs on crops >= 40 px and the
  "hidden" prompt is ignored. Sign damage therefore relies mainly on geometry (lean). Honest limit: these are heuristics, no labelled
  damage data, reported as "possible" problems; the two videos probably contain few real faults so false positives matter more.
- A traffic-light crop with no lit lamp at all (back of a signal or a dead one) is indistinguishable; flagged only after >= 8 dark
  observations and never once lit.
- Latency trade-off of causal smoothing: state changes show up ~1-2 s late (synthetic test: switch at 6.0 s reported at 8.2 s).
- Local CPU test on a 6 s part of clipA: pipeline end-to-end OK (6 lights, 2 signs, markings OK, 0 flagged). Mask2Former on CPU is ~8 s/frame; on the T4 it should be far faster.

## 4. Issues we hit and how each was fixed

| # | Problem | Cause | Fix |
|---|---|---|---|
| 1 | Training data download failed (HTTP 403 from S3) | RDD2022 host refused the direct download | Switched to figshare with range requests |
| 2 | Videos not found on Kaggle | Dataset mount path differs; glob did not match | Glob over `/kaggle/input/**` and later `/kaggle/input/datasets/**`; chunked uploads rebuilt into mp4 in the notebook |
| 3 | ONNX export failed | Kaggle `/kaggle/input` is read-only | Copy weights to `/kaggle/working` before export |
| 4 | Pipeline missed water-filled potholes and manholes | RDD2022 has no such classes | Added classes 4 and 5 via ADE20K water segmentation + puddle blobs and OWLv2 open-vocabulary detection; `absorb_water_overlaps` avoids double counts |
| 5 | "GPU Session cap reached" when starting a notebook | Kaggle allows 2 GPU sessions and a cancelled notebook left a ghost "Cancelling" session | Only one GPU notebook at a time; wait for the running one to finish, then Save & Run All |
| 6 | Notebook 04 could not use extra datasets | Non-interactive sessions cannot attach new datasets | Accepted: fine-tune used RDD only |
| 7 | Map heading drifted ~67 deg on a straight road | Yaw was taken from ground-plane residuals, which are noisy | `_far_yaw`: yaw from far-field features near the horizon, damped ground estimate only as fallback -> clipB net heading -0.8 deg |
| 8 | Wrong horizon row in a local test (58 px) | Assumed instead of measured | Kaggle run estimates it from segmentation: ~192 px for clipA (368 px tall), ~69 px for clipB |
| 9 | `file_upload` rejected the SSD path | The upload tool did not accept a path on the external drive | Copied the zip into `/mnt/user-data/outputs/` and uploaded from there |
| 10 | ONNX benchmark only 8 FPS | `onnxruntime-gpu` lacked `libcublasLt.so.13` so it fell back to CPU | Not a model problem; report TensorRT FP16 (177 FPS) for the GPU number and note the ONNX CPU fallback |
| 11 | Inference v4 failed after 27 s: `AssertionError: an OLD version of roadscan-code is attached` | The fine-tune notebook's output contains a copy of `road-defect-analyzer` (old code); the glob `/kaggle/input/**` picked that copy | Changed the glob to `/kaggle/input/datasets/**/roadscan/__init__.py` so only the real dataset is used; re-ran as v5 successfully |
| 12 | Downloading `submission_outputs.zip` (v5) from Kaggle by browser automation produced no file (two attempts) | The Download click opens a temporary signed-URL tab that closes and cancels non-displayable files (zip); mp4s stay open and can be saved from that tab | FIXED: Joshua downloaded `submission_outputs (1).zip` (28.3 MB) himself; unzipped on the device into `kaggle_results_v2/` (277 files, 34 MB). clipB v5 mp4 md5 matches the copy inside the zip |
| 13 | Stale scheduled check-ins replayed old prompts | Triggers outlived the work they were checking | Treated them as already handled; scheduled new one-off check-ins instead |

Lessons: keep the code dataset as the only source of code on Kaggle; run one GPU notebook at a time; never assume the horizon or camera
height - they change the map scale (distances/speeds are monocular estimates, only rough).
